# 0.1.3.5.2 Substrate Qualification [IMPLEMENT]
## Description

Execute the existing substrate validation protocol against the exact substrate
and configuration selected for the Ω-Synth instantiation, preserving raw
measurements and a reproducible pass/fail assessment. Before execution, resolve
the protocol's internally inconsistent parallelism and integration-bandwidth
thresholds and pin the missing information-integration threshold. Treat any
unresolved threshold or unavailable required test as a qualification failure,
not as an omitted or assumed pass.

## Architecture Contracts

- The coverage matrix assigns a stable check ID to every protocol step and is
  the single source of truth for required procedures, thresholds, units, stress
  conditions, and raw-evidence paths. Threshold resolutions include rationale
  and provenance and may not be overridden by the execution environment.
- Qualification consumes the schema-valid verification evidence produced by
  card 0.1.3.5.1 and compares its configuration and topology digests with the
  pinned expected values before invoking any substrate test. Acceptance by
  card 0.1.3.5.1 establishes substrate identity and conformance to its declared
  baseline, including its configured 4.6 Mbit/s minimum; it does not substitute
  for this card's independent measured qualification at that threshold.
- Each execution writes measurements to a run directory named by a
  caller-supplied run ID. An append-only manifest maps check IDs to
  content-addressed raw-evidence files; result derivation reads only that
  manifest and rejects duplicate, missing, unlisted, or checksum-mismatched
  evidence.
- `substrate-qualification.ts` contains environment-independent validation and
  deterministic PASS/FAIL derivation. It accepts evidence content, seed, and
  observation timestamps as parameters and performs no direct filesystem,
  process, clock, hardware, or network access.
- `substrate-qualification-cli.ts` is the production composition root for the
  injected adapters. It separates `execute` from `derive`, so the documented
  clean-environment rerun derives the report from preserved measurements
  without repeating the 72-hour run or contacting hardware.
- Interrupted, timed-out, unavailable, or adapter-error checks produce explicit
  fail-closed results. A completed run is immutable; retries use a new run ID
  and remain linked to, rather than overwriting, prior evidence.
- Strict TDD proceeds from failing tests for coverage completeness, prerequisite
  digest checks, evidence integrity, threshold boundaries, adapter failures,
  and deterministic report derivation before implementation.

## Threshold Resolution Registry

These values are authoritative for this qualification run and may not be
replaced by the contradictory values in the source protocol or by
host-derived capabilities:

| Check ID | Resolved pass threshold | Resolution and provenance |
|---|---|---|
| `PARALLELISM_MIN` | At least 10 independently schedulable, co-active processing units for L1–L10 | The protocol says 9 but enumerates L1–L4, L5, L6, L7, L8, L9, and L10: ten units. L0 and L11 are interfaces and are not counted. Logical schedulability, rather than physical core count, keeps the criterion applicable to the selected CPU substrate. |
| `INTEGRATION_BANDWIDTH_MIN` | At least 4.6 Mbit/s sustained payload bandwidth at the pinned 40 Hz cadence | The protocol's own terms at 40 Hz are `512 × 32 × 40 = 655,360` bit/s for workspace broadcast and `12 × 256 × 32 × 40 = 3,932,160` bit/s for inter-core traffic, totaling 4,587,520 bit/s and rounded upward to 4.6 Mbit/s. Card 0.1.3.5.1 now pins the same value as a baseline configuration minimum, but its conformance evidence is not measurement evidence; this check must independently measure at least 4.6 Mbit/s or fail. |
| `INTEGRATION_METRIC_MIN` | Bootstrap 95% confidence-interval lower bound for normalized Ψ-G is at least 0.65 | `metric-evaluation.md` predicts normalized Ψ-G of 0.65–0.90 for Ω-Synth, while `metric-definitions.md` requires bootstrap confidence intervals. Using the lower predicted bound as the measured minimum prevents a merely positive but practically negligible result from passing. |

All three checks use inclusive boundaries. Units and normalization are part of
the contract; an unnormalized Ψ-G value, a bandwidth value that includes
protocol overhead, or evidence without the specified confidence interval is
out of schema and therefore fails.

## Acceptance Criteria

- A protocol coverage matrix maps every check and pass criterion in
  `substrate-architecture.md` to a test procedure, threshold, raw-evidence
  location, and result; the matrix explicitly resolves the parallelism count,
  integration-bandwidth minimum, and information-integration threshold
- Qualification refuses to start unless the instantiation configuration and
  topology digests match the outputs accepted by card 0.1.3.5.1; matching
  digests or configured minima do not imply that this card's measured thresholds pass
- Tests are written before the qualification harness and prove failure for a
  missing check, unresolved threshold, digest mismatch, unavailable required
  stress condition, malformed evidence, and threshold violation
- Every protocol step is executed against the pinned configuration, including
  functional equivalence, temporal fidelity, information integration,
  degradation sweeps, the full 72-hour stability run, and at least one named
  deployment-context stress test
- Raw measurements preserve units, uncertainty, test conditions, caller-supplied
  timestamps and seeds, configuration and topology digests, tool versions, and
  immutable evidence checksums
- Filesystem, process, clock, hardware-control, and network interactions are
  injected behind interfaces; automated tests use fakes and the report records
  the concrete adapters used by the real run
- Each threshold and protocol-level pass criterion has an explicit measured
  PASS or FAIL result; skipped, unavailable, or out-of-schema checks force the
  overall result to FAIL
- The schema-valid qualification report identifies deviations and limitations,
  links every conclusion to raw evidence, and gives a clean-environment rerun
  command that reproduces result derivation from preserved measurements
