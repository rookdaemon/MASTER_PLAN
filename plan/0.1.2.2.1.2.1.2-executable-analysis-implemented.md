# 0.1.2.2.1.2.1.2 Executable Analysis Implemented [ARCHITECT]
## Description

Implement the executable calibration analysis specification using strict TDD. Encode the frozen protocol's deterministic splitting, fitting, inference, sensitivity, failure, and leakage-prevention rules. Inject dataset and held-out access, optimizer, hashing, file-system and runtime behavior; pass freeze records and timestamps explicitly into methods.

## File Manifest
- src/irsm-calibration/analysis.ts
- src/irsm-calibration/__tests__/analysis.test.ts

## Architecture Contract

`analysis.ts` exports pure orchestration functions for eligibility and exclusion logging, frozen grouped partition construction and verification, candidate fitting, held-out scoring and inference, and prespecified sensitivity reporting. Each function receives immutable records plus one dependency object; no function reads clocks, environment variables, files, network resources, or held-out outcomes directly.

The dependency object defines injected dataset and held-out readers, SHA-256 hashing, optimizer execution, append-only persistence, and deterministic bootstrap sampling. Decision, freeze, access, and deviation timestamps are caller-supplied parameters. The held-out reader exposes outcome-free records separately from an outcome-release method that validates the complete freeze record and supplied access timestamp before returning labels.

All externally persisted manifests, diagnostics, exclusions, deviations, estimates, confidence intervals, sensitivity results, and failures use exported typed records with stable reason codes. Canonical ordering is by UTF-8 lexicographic identifier order except where the protocol explicitly requires hash or numeric tuple order; hashing uses a documented canonical JSON serializer with recursively sorted object keys, preserved array order, finite JSON numbers, and UTF-8 bytes. Invalid identifiers, duplicate identifiers, non-finite values, hash mismatches, optimizer failures, insufficient samples, and non-estimable statistics return typed failures rather than throwing dependency-specific errors.

The test file is the executable conformance matrix: each protocol section and rule has a named test or table-driven case, including sparse-stratum pooling, mixed-group stratum ties, minimum-sample gates, all-start/all-candidate failure, tolerance tie-breaking, clustered stratified bootstrap behavior, finite-resample thresholds, Holm handling, substrate reporting, every prescribed sensitivity, and reciprocal artifact-reference verification. Tests use fakes for every dependency and fixed caller-supplied timestamps.

## Acceptance Criteria
- Tests are committed before implementation and cover deterministic splitting and fitting, whole-group isolation, identifier-overlap rejection, deterministic tie-breaking, convergence and failure behavior, and sensitivity procedures
- Held-out outcomes are denied until the caller supplies a valid model-freeze record and access timestamp
- The implementation exposes injected interfaces for dataset access, held-out access policy, optimization, hashing, file-system, and runtime behavior
- Public functions and persisted outputs conform to the architecture contract's immutable inputs, typed results and failures, canonical ordering, serialization, and stable reason codes
- Repeated runs with identical inputs and injected dependencies produce identical partitions, fitted results, inference outputs, and failure records
- Tests demonstrate conformance between the executable procedures and every corresponding rule in the frozen protocol
