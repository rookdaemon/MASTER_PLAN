# 0.1.3.5.1 Instantiation Specification [ARCHITECT]
## Description

Translate the Ω-Synth reference architecture into an executable, versioned
instantiation specification. Pin every architecture, runtime, substrate, and
measurement dependency needed to reproduce the system without relying on
unstated environment assumptions. Resolve every suggested range and alternative
in the reference design to one named baseline value or implementation, while
keeping permitted experimental overrides explicit and machine-validated.

## File Manifest

- docs/neural-architectures/architecture-designs/hybrid-synthesis-design.md (architecture input)
- docs/consciousness-engineering/system-instantiation-specification.md (planned specification)
- configs/omega-synth/baseline.yaml (planned machine-readable baseline)
- schemas/omega-synth-instantiation.schema.json (planned configuration contract)
- tests/omega-synth/test_instantiation_specification.py (planned conformance and clean-environment verification)

## Architecture Contracts

- `baseline.yaml` is the single source of truth for every resolved architecture,
  runtime, substrate, and measurement value. The prose explains those choices
  and references configuration keys; it must not define competing defaults.
- The schema is closed at every object boundary and encodes cross-field topology
  constraints that JSON Schema cannot express as named verifier checks.
- Verification proceeds schema validation → semantic topology validation →
  deterministic topology-manifest construction → digest comparison. The digest
  is SHA-256 over UTF-8 canonical JSON with recursively sorted keys, no
  insignificant whitespace, and arrays retained in declared order.
- The topology manifest contains only normalized nodes, directed edges, tensor
  shapes, update order, initialization metadata, and invariant parameters.
  Runtime observations and host-specific paths are evidence, not digest inputs.
- A caller supplies the seed, observation timestamp, filesystem adapter, process
  runner, clock, and network policy. Production adapters are selected only by
  the command entry point; specification and verification code depend solely on
  injected interfaces, and tests use denying or in-memory fakes.
- Unknown keys and implicit defaults are errors. Experimental overrides must be
  supplied as a separate validated overlay, recorded in evidence, and produce a
  distinct configuration and topology digest without mutating the baseline.
- Each failure reports a stable check identifier, configuration path, expected
  value, and actual value so substrate qualification can consume results
  without parsing prose.

## Acceptance Criteria

- The specification enumerates L0–L11, every required directed connection and
  recurrent loop, tensor dimensions, update ordering, initialization rule,
  activation function, gating behavior, and non-zero inter-core weight invariant
- The baseline configuration resolves every range, optional path, and
  implementation alternative in the architecture input; the schema rejects
  missing, unknown, out-of-range, and topology-breaking values
- Runtime, package and toolchain versions are locked; the target compute
  substrate records processor/accelerator requirements, numerical precision,
  memory minimum, driver/firmware constraints, and supported platform
- Build and initialization consume an explicit caller-supplied seed and
  timestamp, perform no undeclared network or filesystem access, and produce a
  configuration digest plus a topology manifest
- One documented command builds and verifies the baseline in a clean
  environment using injected filesystem, process, clock, and network adapters;
  tests use fakes for those adapters
- Verification fails on any node, edge, dimension, parameter, version, seed, or
  digest mismatch and records the exact mismatch; the passing fixture proves
  that the instantiated topology equals the checked-in baseline
- The prose specification cross-references the baseline, schema, verification
  command, expected topology digest, and the evidence consumed by substrate
  qualification card 0.1.3.5.2
