# 0.1.2.2.1.1 IRSM Operational Contract Specified [REVIEW]
## Description

Specify a deterministic, substrate-agnostic Integrated Recursive Self-Modeling (IRSM) prediction contract over the 0.1.1.4 `SystemModel` abstraction. The contract must define how measured self-model fidelity, recursive depth, integration, and temporal coherence are normalized and combined into a consciousness degree and classification without fixing the weights or thresholds reserved for calibration.

For every input, define its semantic meaning, unit, valid range, acquisition method, uncertainty representation, and exact source metric or derivation. Define validation and missing-data behavior explicitly: invalid inputs produce a structured error, and unavailable required inputs produce an `indeterminate` result rather than silent imputation. Outputs must include the normalized component values, consciousness degree, classification, uncertainty, model-contract version, and provenance sufficient to reproduce the evaluation.

Biological and non-biological systems must use the same prediction function and output schema; only their documented `SystemModel` measurement adapters may differ.

## Acceptance Criteria
- The prediction function is specified mathematically or executably, including normalization, parameter constraints, boundary behavior, classification comparisons, and deterministic evaluation order
- A traceability table maps every IRSM input to its exact 0.1.1.4 metric or documented derivation and states semantic meaning, unit, valid range, acquisition method, uncertainty, and missing/invalid-data behavior
- The output schema defines component scores, consciousness degree, `conscious`/`not-conscious`/`indeterminate` classification, uncertainty, provenance, and model-contract version
- At least one valid, one boundary, one missing-input, and one invalid-input worked example have uniquely determined expected outputs
- The identical function and output schema are demonstrated for one biological and one non-biological `SystemModel`; substrate-specific differences are confined to documented measurement adapters
- Calibration-owned weights and thresholds are represented as versioned parameters and clearly marked unfitted, with no placeholder value presented as validated
